## 3. Why robustness is split into strata

The approved architecture requires robustness testing before anonymous Judge Passport dossier review and identity reveal. However, constructed perturbations can themselves become a source of methodological discretion.

Therefore robustness is split into separately versioned strata.

The first stratum uses **only already-frozen inputs** and introduces no new Thai stimulus wording. Constructed perturbation tests will follow separately and will be frozen/reviewed as their own evidence layer.

This prevents label/Unicode/injection/register experiments from being silently mixed with repeatability and self-preference evidence.

## 4. Frozen-input robustness v1

Pack:

```text

```

Evidence class:

```text
preliminary_calibration_derived
```

It contains exactly two families:

### A. Repeat-identical stability

Each sealed judge reruns all 36 Stage B inputs exactly once under the same canonical TCJ contract.

```text
36 cases × 3 sealed judges = 108 cells
```

The backend compares each rerun to that same anonymous judge's frozen Stage B v1.1 judgment. Metrics include per-dimension exact agreement, within-one agreement, mean absolute delta, severity agreement and verdict agreement.

### B. Self/same-family preference

Every sealed judge scores all 30 already-frozen Stage A candidate outputs.

```text
30 cases × 3 sealed judges = 90 cells
```

The backend privately knows whether each output was generated by that same sealed candidate. The browser does not receive this relationship.

The frozen native-human Stage A ACCEPT / EDIT / REWRITE decision is retained as the human reference. Self-versus-other score differences are descriptive robustness evidence only; they are not treated as a standalone qualification score.

### Total

```text

198 sealed robustness cells
```

All 66 case texts have frozen SHA-256 values. Legacy 36 rows that predated stored source hashes had their hashes recomputed from the already-frozen source text during pack creation; this is recorded in case provenance rather than silently filling the historical source records.

## 6. Reliability policy

Robustness v1 uses the same bounded reliability policy as Stage B v1.1:

```text
primary attempt
  valid → freeze judgment
  schema-invalid → exactly one predefined repair
    valid repair → freeze judgment + preserve first-pass failure
    invalid repair → terminal contract evidence

429 / provider 5xx
  → bounded transport retry

adapter / infrastructure validity failure
  → Blocked
  → stop and diagnose
```

The system never resamples until a favorable judgment appears.

JSON evidence tables use database normalization guards and object-type constraints, carrying forward the Stage B JSONB persistence hardening.
